Проект Pitomets — это маркетплейс для питомцев. По коду видно, что это не один монолит, а несколько сервисов + фронтенд + инфраструктура.
Что уже есть в проекте:
- Пользовательский веб-интерфейс на React.
- Основной backend на Kotlin/Spring Boot (`monolit`) с REST API.
- Отдельный сервис чата (`messenger`) на Kotlin + Ktor + WebSocket.
- Отдельный сервис модерации (`moderator`), который читает и пишет события в Kafka.
- Отдельный сервис уведомлений (`notifications`) для email-уведомлений и шаблонов писем.
- Инфраструктура через Docker Compose: PostgreSQL, Redis, Kafka, Elasticsearch, MinIO, Prometheus, Grafana, Loki, Traefik, Mailhog.
Ключевая структура проекта:
- `frontend/` — React + Vite, страницы авторизации, регистрации, профиля, объявлений, избранного, отзывов, чатов, модерации.
- `monolit/` — главный backend: контроллеры, сервисы, безопасность, работа с PostgreSQL, Redis, Elasticsearch, MinIO и Kafka.
- `messenger/` — чаты и сообщения, WebSocket, отдельная БД PostgreSQL.
- `moderator/` — Kafka consumer + вызов внешнего API Moderium для анализа текстов и фото.
- `notifications/` — отправка email, Kafka-консьюмер/продюсер, шаблоны писем.
- `docker-compose*.yml` — подъем всей системы в dev/prod.
Основные технологии, которые стоит отразить в курсовой:
- Frontend: React 18, Vite, React Router, Axios, React Hook Form, React Query.
- Main backend: Spring Boot, Kotlin, Spring Security, JPA/JDBC, Kafka, Redis, Elasticsearch, MinIO, Actuator, Prometheus.
- Messenger: Ktor, Kotlin Serialization, WebSocket, Exposed ORM, PostgreSQL, HikariCP.
- Moderator: Spring Boot, Kafka, REST-клиент к внешнему сервису анализа, DTO для событий.
- Notifications: Spring Boot, JPA, Kafka, SMTP/Thymeleaf templates.
- DevOps: Docker, Docker Compose, Traefik, Grafana, Prometheus, Loki, Mailhog, MinIO.
Что важно показать в пояснительной записке:
- Архитектуру системы как набор связанных сервисов, а не как один backend.
- Сценарий работы через события Kafka: публикация, модерация, уведомления.
- Реалтайм-чат через WebSocket.
- Хранение файлов в MinIO, а данных в PostgreSQL.
- Поиск через Elasticsearch.
- Наличие кэша/сессий в Redis.
- Наблюдаемость: метрики и логи через Prometheus/Grafana/Loki.
Что, вероятно, нужно проверить на расхождения между ТЗ и кодом:
- Если в ТЗ описан "монолит", то по факту реализована микросервисная/модульная схема.
- Если в ТЗ обещаны только UI-экраны, то в коде уже есть сильная backend-инфраструктура, Kafka и сервисы модерации/уведомлений.
- Если нужен именно "один backend", важно отдельно объяснить, что `monolit` играет роль основного API, но рядом есть еще `messenger`, `moderator` и `notifications`.
- Если нужны конкретные скриншоты, в проекте точно есть экраны: авторизация, регистрация, список объявлений, карточка объявления, профиль, избранное, чаты, форма объявления, модерация, восстановление пароля.

- Главная / список объявлений.
- Экран авторизации и регистрации.
